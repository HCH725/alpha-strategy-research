## Economic mechanism

### Research interpretation

Exhaustion-reclaim machine with a trend-strength bouncer, long-only, edge-triggered both legs. Unlike price-only RSI records (S00139 washout, connors, ema-rsi-pullback: averages of close-changes), this system never fires on a smoothed-momentum wiggle: the %R leg is an unsmoothed positional readout of where the close sits inside the trailing 14-bar high/low range, so entries print only on bars that physically leave the bottom quintile of that range. Unlike the pool's pure-%R record (identical 14/-80/-20 geometry, no gate), every entry here must additionally prove `ADX(14) >= 20` on the same bar — flat-range chop that prints qualifying %R reclaims with dead trend strength is turned away at the door, so the system buys exhaustion only when directional commitment already exists. Unlike ADX-family records (DI-cross systems that trade the trend-following leg itself), ADX here never triggers anything: it is a pure veto with no exit role — the exit is the mirror %R cross-down alone, so a position opened under strong trend rides until range-position failure, never until trend failure. The coded consequence is a picky participation buyer: fewer, trend-backed exhaustion entries, each ended on a single overbought-failure edge with no stop to second-guess it.

## Signal

Exact rule as pinned (any other %R construction, period, threshold, strictness, ADX construction, gate, exit leg, fill, frame, book, or ordering is a different, unpinned rule). All identifiers below are the program's own; the vectorized twin `generate_signals` is the single source of truth and the scalar delegate defers to it:

```text
hh[t]      = max(high[t-13..t])
ll[t]      = min(low[t-13..t])
wr[t]      = -100 * (hh[t] - close[t]) / (hh[t] - ll[t])
adx[t]     = ADX(14) via file's own _adx (TR + directional movement, rolling-mean smoothing, second 14-bar mean of DX)
entry      = (wr[t-1] < -80) AND (wr[t] >= -80) AND (adx[t] >= 20)
exit_      = (wr[t-1] > -20) AND (wr[t] <= -20)
guard      = none coded; NaN legs compare false and twin applies fillna(False) (see Required data)
```

- Trade events: `entry_signal=True` with `direction="long"` on gated-reclaim bars; otherwise `entry_signal=False` with `exit_signal=bool(exit_)` on the same return. Both legs are EDGES (fire only on the cross bar) — there is no level-hold leg anywhere: a book parked above -80 without a fresh cross holds, it does not re-enter; a book parked below -20 without a fresh cross holds, it does not re-exit. The ADX gate applies to the entry leg only — no bar's exit leg reads ADX in any form.
- Exact boundaries (pinned semantics): entry admits equality on the current bar (`wr >= -80`, a touch-up reclaim fires) but demands strict oversold on the prior bar (`prev_wr < -80`); exit admits equality on the current bar (`wr <= -20`, a touch-down failure fires) but demands strict overbought on the prior bar (`prev_wr > -20`). A print landing exactly on its threshold on the prior bar fires nothing on either leg. Zero-range bars (`hh == ll`) divide zero-by-zero to `NaN`, and `NaN` legs are forced `False` by the twin's `fillna(False)` — flat tapes print nothing by construction (fenced, not repaired).
- Both-legs coexistence (coded, no researcher ordering needed): entry and exit are mutually exclusive by thresholds — the prior bar cannot print %R both strictly below -80 AND strictly above -20 (-80 < -20 always), so no bar can satisfy both prior-bar gates at once. No priority rule can ever fire; no same-bar dual-fire sequencing is left to any engine.
- Direction: long-only with an explicit pre-first-signal flat state plus the warmup flat below. The scalar delegate returns the `direction="long"` literal on every bar; zero `short` tokens ship anywhere; the base class pins `supported_trade_modes == {"long_only"}` and `mirror_short_safe == False` — a two-sided reading would contradict the file and its base. The long-only book expresses unchanged on a spot venue (see Execution assumptions).
- Exits and risk (explicit): the %R cross-down through -20 is the sole position-ending path. Stop loss, take profit, trailing-stop order, and time limit are absent from the file in every form (0 `stop` / 0 `limit` / 0 `profit` / 0 `trail` tokens) and recorded as explicitly disabled, not as defaults to be assumed. `confidence` (`min(1.0, curr_adx / 40)` on ADX-passing bars, else `0.0`) and the `indicators` dict are diagnostic — neither conditions any order line.
- Position rule (predeclared researcher pin): single-unit; a positioned book treats further entry-only bars as hold-no-ops (no pyramiding, no averaging); a flat book treats exit-only legs as no-ops; re-entry re-arms on any qualifying gated-reclaim bar after any exit (no cooldown specified — explicitly none, not invented). Pre-first-signal and warmup bars are flat by record rule. No `position_size` / `position_avg_price` / `openprofit` / `opentrades` reference exists in the file, so no position-aware state conditions any signal.

The `compatible_regimes` set (`{"TREND_UP", "RANGE", "VOLATILE"}`) is metadata never read by the signal path (which takes only `df`/`params`); treating the label as a gate would be a different, unpinned rule.
